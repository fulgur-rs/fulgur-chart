# 横棒 x 軸目盛ラベルの canvas 端はみ出し修正

## 背景

`build_horizontal` は x 軸の目盛ラベルを `plot_right` 上に中央寄せで描画している。
現在の `plot_right` は canvas 右端と右凡例帯だけを考慮しているため、最大目盛の文字幅の
半分が canvas 外へ出ることがある。たとえば幅800の横棒で目盛が `100000` になると、
ラベルの右半分が切れる。

## 方針

- x 軸目盛に実際に表示する `fmt_num` 済み文字列の端点幅を `TextMeasurer` で計測する。
- `plot_right` は最後の目盛ラベル幅の半分を右端余白として使い、左端は必要な場合だけ先頭ラベル幅を独立して補う。
- 目盛、棒、グリッド、軸線は同じ `plot_left`/`plot_right` を使い、中央寄せの目盛ラベル配置は維持する。
- 基準境界が狭すぎる場合でも `MIN_HORIZONTAL_PLOT_WIDTH`（1px）を確保し、余白は利用可能幅に応じて比例縮小する。
- フォントサイズや計測結果が f32 の有限範囲を超える場合も、非有限値を境界計算へ伝播させない。
- 右凡例がある場合も、凡例帯と目盛ラベル余白を重ねずに確保する。

## 代替案と不採用理由

1. 最終目盛だけ `Anchor::End` にする案は、端の目盛だけ配置規則が変わり、他の目盛との整列が不自然になる。
2. canvas 寸法を拡張する案は、利用者が指定した出力サイズを変更するため採用しない。

## テスト

- `labels=[5,500,95000]` の横棒で、最大目盛 `100000` の中央寄せラベルが canvas 内に収まることを検証する。
- 全負値の横棒で右端余白が左端の最大幅目盛に引っ張られないことを検証する。
- 長いカテゴリラベル・右凡例を含む幅30pxの canvas で最小プロット幅を検証する。
- `fontSize=1e40` の入力でプロット境界が有限かつ非縮退であることを検証する。
- 現行ブランチでは対数軸の実装がまだないため、今回の回帰テストは線形軸に限定する。余白計算は軸種別ではなく実際の表示文字列幅だけに依存するため、将来の対数軸にも同じ境界計算が適用される。
- 既存の横棒レイアウト・レンダリングテストと crate の品質ゲートを実行する。
